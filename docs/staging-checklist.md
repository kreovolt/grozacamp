# Чек-лист тестового адреса (T21) и запуска

Что проверить на настоящем хостинге. Пункты зависят от хостинга, поэтому в коде их закрыть нельзя.
Источник: финальное ревью ветки `feat/site-v1` (`.superpowers/sdd/2026-11-25-grozacamp-site/final-review.md`, раздел «Recommendations», пункты M7 и «REMOTE_ADDR за прокси»).

## 1. Хостинг: что должно быть

Проверить скриптом проверки хоста (T21) или вручную через `phpinfo()` и временно выложенный файл. Файл после проверки удалить.

- [ ] PHP ≥ 8.1.
- [ ] GD с JPEG, PNG и WebP (`gd_info()`: `JPEG Support`, `PNG Support`, `WebP Support`).
- [ ] Расширения `fileinfo`, `exif`, `zip`, `mbstring`.
- [ ] `display_errors = Off`. Bootstrap на staging и prod тоже выключает показ ошибок, но настройка хостинга должна совпадать.
- [ ] `upload_max_filesize` ≥ 20M, `post_max_size` ≥ 21M.
- [ ] Хостинг разрешает `memory_limit` и `ini_set`: фото обрабатываются с запасом памяти, сессии настраиваются через `ini_set`.
- [ ] `AllowOverride` разрешает `.htaccess`. Проверка: запрос `/uploads/x.txt` (положить пустой файл) отвечает 403. Если отвечает 200, `.htaccess` не работает: загрузки выполнялись бы как обычные файлы, а служебные папки были бы открыты.
- [ ] HTTPS-сертификат на основном и тестовом адресах.
- [ ] Ящик SMTP для писем с заявок: адрес, пароль, порт 465/SSL, отправитель. Пробное письмо доходит до `mailTo`.
- [ ] Cron: `php scripts/uploads-gc.php` раз в сутки. Скрипт убирает лишние загрузки, переносит в карантин файлы, нужные только истории, и чистит карантин `storage/quarantine`. Первый запуск сделать вручную с `--dry-run`.
- [ ] `/.well-known/acme-challenge/` доступен по http: продление сертификата Let's Encrypt. `.htaccess` эту папку не закрывает, PHP её не перенаправляет: файлы отдаёт Apache.

## 2. Выкладка

- [ ] Скрипт выкладки не трогает `config/local.php`, `storage/` и папку загрузок (`public/uploads/`, в общей раскладке — `uploads/`). Иначе файл разработчика с `env=dev` или пустой файл попадёт на сервер. Без `config/local.php` сайт теперь сам считает себя боевым: админка показывает «Сайт не настроен» (503), формы показывают телефон.
- [ ] В `config/local.php` на сервере есть `env` (`staging` или `prod`), `baseUrl` с `https://`, `appSecret` (от 32 знаков, не из примера), `mail.*`, а для staging ещё `staging.user` и `staging.pass`.
- [ ] Общая раскладка (сайт в одной папке с кодом): загрузки лежат в `uploads/` рядом с `index.php` (`Layout::uploadsDir`). Вместе с ней выложен `uploads/.htaccess` (копия `public/uploads/.htaccess`).

## 3. Обратный прокси и адрес посетителя (REMOTE_ADDR)

Отложено из ревью: проверить можно только на настоящем хостинге.

- [ ] С двух разных устройств (например, Wi-Fi и мобильный интернет) открыть временный файл, который выводит `$_SERVER['REMOTE_ADDR']`. Адреса должны различаться. Если оба раза виден один адрес, перед Apache стоит прокси (nginx) без `mod_remoteip`. Тогда все посетители — «один адрес», и любой из лимитов закрывает сайт для всех:
  - лимит форм: 12 заявок за 10 минут;
  - блокировка входа по адресу;
  - лимит новых сессий админки.
- [ ] Если прокси есть, попросить хостинг включить `mod_remoteip` (или его аналог) с настоящим адресом в `X-Forwarded-For`. Адрес прокси записать в `trustedProxies` в `config/local.php`. Только тогда PHP верит заголовку `X-Forwarded-Proto: https`.
- [ ] HTTPS снимается на прокси (в Apache приходит http): без `trustedProxies` каждый запрос получал бы 301 на https, то есть бесконечную переадресацию. Проверка: `curl -I https://…/` отвечает 200, а не 301.

## 4. HTTPS

PHP отвечает 301 на https-адрес из `baseUrl` (тот же путь и строка запроса) на staging и prod. Ответ даётся до пароля тестового адреса и до входа в админку. HSTS отправляется только на prod.

- [ ] `curl -I http://grozacamp.ru/booking/?smena=x` отвечает 301 с `Location: https://grozacamp.ru/booking/?smena=x`. Тестовый адрес проверить так же.
- [ ] `curl -I https://grozacamp.ru/` отдаёт `Strict-Transport-Security` (только prod).
- [ ] Статические файлы (`/assets`, `/uploads`) Apache отдаёт без PHP, поэтому по http они переадресуются, только если это сделать в `.htaccess`. Решить, когда станет ясно, что с прокси (п. 3):

  ```apache
  RewriteCond %{HTTPS} off
  RewriteCond %{HTTP:X-Forwarded-Proto} !https
  RewriteCond %{REQUEST_URI} !^/\.well-known/acme-challenge/
  RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
  ```

  Правило ставится в начало блока `mod_rewrite`. Если прокси не передаёт `X-Forwarded-Proto`, правило зациклит сайт, поэтому оно не включено заранее.

## 5. Тестовый адрес: закрыт целиком (M7)

Отложено из ревью. Пароль тестового адреса проверяет PHP. Файлы `/uploads/*` и `/assets/*` Apache отдаёт сам, без пароля и без `noindex`. До T22 это не страшно, но потом там окажутся настоящие сканы клиента.

- [ ] В vhost или `.htaccess` тестового адреса включить Basic-авторизацию Apache (`AuthType Basic`, `AuthUserFile` вне корня сайта). Если это невозможно — `Header set X-Robots-Tag "noindex, nofollow"` и запрет `/uploads/` для всех, кроме своих адресов.
- [ ] Без пароля: `/` отвечает 401, `/uploads/docs/<любой>.pdf` отвечает 401 (или 403), у ответов есть `X-Robots-Tag: noindex, nofollow`.

## 6. Проверка после выкладки (smoke)

- [ ] `http://` отвечает 301 на `https://` (п. 4).
- [ ] Тестовый адрес без Basic отвечает 401, с ним — 200 и `X-Robots-Tag: noindex, nofollow`.
- [ ] `/storage/data/users.json`, `/config/local.php`, `/vendor/autoload.php`, `/composer.json` отвечают 403 или 404, в общей раскладке тоже.
- [ ] `/uploads/x.txt` отвечает 403 (п. 1).
- [ ] `/assets/css/app.css?v=…` отдаёт `Cache-Control: public, max-age=31536000, immutable`, несуществующий `/assets/nope.css` — 404.
- [ ] `/admin/` без входа ведёт на форму входа, а не на «Сайт не настроен» (иначе `config/local.php` не подхватился).
- [ ] Пробная заявка с формы приходит письмом. В `storage/logs/forms.log` — строка `sent` без данных формы.
- [ ] «Скачать резервную копию» в админке отдаёт zip с `data/`, `uploads/` и `quarantine/`.

## 7. Перед запуском (T22–T23)

- [ ] «Готовность к проверке» в админке вся зелёная. Потом редактор сам предупреждает, если сохранение уберёт пункт приказа.
- [ ] Метрика: юридическая проверка порядка «счётчик до согласия на cookie». Метрика включается, только когда задан `metrikaId`.
- [ ] Тексты клиента: `content/drafts-for-client.md`.
- [ ] Фото первого экрана: если клиент хочет другое, его загружают в «Главная → Фото первого экрана». Картинка для соцсетей (OG) остаётся прежней.
